# Журнал дефектів приймання

Пакет 8.1, функціональний baseline `ea47b13f4a4b08665279307bc9f66db63703648a`, HromadaHR 0.1.0 / SQLite v21. Windows GUI-приймання ще не виконано. Нових підтверджених P0/P1 під час технічної перевірки 8.1 не виявлено; це не доказ їх відсутності в ручному прогоні. Відкриті можливості/обмеження — у [RELEASE-GAPS](RELEASE-GAPS.md), а не вигадані дефекти.

## Серйозність і статуси

| Рівень | Критерій |
|---|---|
| P0 — критичний | Втрата/пошкодження даних, небезпечний restore, порушення цілісності БД |
| P1 — високий | Помилковий кадровий результат/розрахунок, обхід перевірок, основна операція недоступна |
| P2 — середній | Помилковий перехід/редагування/UI із відомим обхідним шляхом |
| P3 — низький | Косметика, відступи, другорядні підписи/візуальна неузгодженість |

Статуси дефекту: NEW → CONFIRMED → IN_PROGRESS → FIXED → VERIFIED → CLOSED; також NEEDS_INFO, DEFERRED (з обґрунтуванням/відповідальним), REJECTED (причина). FIXED означає наявний коміт, VERIFIED — повтор відтворення на цьому SHA; не змішувати зі статусами сценарію PASS/FAIL/BLOCKED/NOT_RUN/NOT_APPLICABLE.

При P0/P1 зупинити залежний тест, зберегти стан синтетичного середовища та докази; без перезапису/очищення БД «для перевірки ще раз». Пошкоджені файли/аварійні ін’єкції — лише disposable VM/БД. Виправлення — окреме погоджене завдання, не приховане розширення 8.1.

## Докази й конфіденційність

Використовувати лише синтетичні E01–E07 та тимчасові вигадані записи. Не додавати до Git реальні БД, резервні копії, ПІБ, РНОКПП, паспорти, банківські дані, персональні скриншоти, абсолютні приватні шляхи користувача, логи чи секрети. Службові номери на кшталт ТЕСТ-001 допустимі. Великі навіть синтетичні БД/відео зберігати в погодженому сховищі доказів поза репозиторієм, у картці — ідентифікатор і checksum.

Помилка тестового середовища, відсутній harness чи еталон означає BLOCKED сценарію, а не автоматичний продуктний P1. Погоджено відкладений DOCX/installer — release gap; не заявляти регресію функції, якої ще немає. При підозрі на неправильний нормативний результат не вигадувати правовий еталон: зберегти факти й залучити відповідального кадровика.
