# Передавання контексту Codex

## Звідки продовжувати

Працюйте лише в `Anatol1ch/HromadaHR`. Базовий погоджений код етапів 1.1–1.3: `8647df8873a70757511a70e61b0bccdfdb786bfb`. Етап 1.4 додає документацію та правило ігнорування локального `reference/`, без змін коду застосунку. Поточний HEAD і Git-стан завжди перевіряйте командами Git, а не за цим текстом.

HromadaHR 0.1.0 — незалежна Windows-основа, українська оболонка та мінімальний безпечний IPC після етапу 2.1. До роботи з реальними кадровими даними застосунок ще не готовий. IPC-інфраструктура підготовлена до 2.2 SQLite; не починайте 2.2 без окремого завдання. Поточна зміна базується на `9a341d15dfa59bd46d6512f4d54c9fcbc5b633e6`, гілка `main`; перед початком робоче дерево було чистим.

## Що завершено

- 1.1: Electron/React/TypeScript/Vite, pnpm, безпечне вікно, preload без API, окремі dev/built-профілі та команди збірки.
- 1.2: оболонка з семи розділів, breadcrumbs, Alert/DataState, відібрані правила HromadaAID.
- 1.2.1: семантична бузково-фіолетова палітра та ресурс герба в `assets`.
- 1.3: пілотний блок Вишнівської громади, тематичні стани нереалізованих розділів, усунення оманливої кнопки огляду; діагностика старого dev-вікна.
- 1.4: технічна звірка та комплект документації. Не виявлено проблем, які вимагали б змін архітектури або runtime-коду.
- 2.1: спільні типізовані контракти `shared/ipc.ts`, обмежений `window.hromadaHR.system.getInfo()`, реєстратор Main із перевіркою актуального вікна/WebContents/mainFrame/URL, Zod-валідацією аргументів і відповіді та контрольованими помилками. Єдина операція повертає назву, версію й dev/built. У налаштуваннях показано реальну версію через IPC.
- Sandboxed preload збирається наявним Vite в один CommonJS-файл; окремих залежностей для bundling/тестів не додано. Додано лише runtime-залежність Zod 4.6.7. Main тепер у `dist-electron/electron/main.js`, preload у `dist-electron/preload.cjs`, shared у `dist-electron/shared/`; шляхи запуску та ресурсів оновлено разом.

## Карта файлів та обмеження

Починайте з `AGENTS.md`, цього документа, далі цільово читайте [ARCHITECTURE.md](ARCHITECTURE.md) та [DECISIONS.md](DECISIONS.md). Команди середовища — у [README](../README.md).

Ключові файли: `package.json`/lockfile і `tsconfig*.json`; `electron/main.ts`, `electron/ipc.ts`, `electron/preload.cts`, `shared/ipc.ts`; `vite.config.ts`, `vite.preload.config.ts`, `index.html`; `src/App.tsx`, `src/env.d.ts`, `src/main.tsx`; `tests/ipc.test.mjs`; `src/components/Alert.tsx`, `DataState.tsx`; `src/styles.css` і `src/styles/`; `assets/community-coat.png`.

Зберігайте sandbox/contextIsolation, відсутність Node integration і контроль навігації. Не послаблюйте CSP для маскування помилок ресурсів. HromadaAID — лише джерело для читання на коміті `16582ce252086bb39d2276ac3c1de90e4895f21f`; жодних спільних runtime-пакетів або приєднання Git-історії. `reference/` — локальні матеріали, не змінювати й не додавати до Git; застосунок використовує `assets/community-coat.png`.

Відсутні SQLite/міграції, локальна авторизація, майстер першого запуску, предметні IPC, кадрові операції, відпустки, стаж і ранги, документообіг, резервування, оновлення та інсталятор. Погоджені майбутні рішення не є дозволом реалізувати їх у поточному завданні.

Майбутню перевірку авторизації слід додавати в Main після sender/argument validation перед виконанням захищених операцій. Зараз є тільки публічна діагностика; немає акаунтів, сеансів чи заглушки доступу. Нові можливості потребують окремих методів preload, контрактів і валідованих обробників; універсальний renderer invoke заборонений.

## Перевірки та відомий сценарій старого інтерфейсу

На 2.1 виконано `pnpm typecheck`, `pnpm test` (9/9), `pnpm build`, `git diff --check`. Тести виконують реальний скомпільований реєстратор з Electron doubles та зібраний preload у Node VM: успішний dev/built-виклик, некоректні аргументи, allowlist/незареєстровані канали, сторонній sender, підфрейм/відсутній frame/чужий URL, закрите/знищене/замінене вікно, контрольовані помилки, відсутність універсального API й нормалізація транспортних помилок. Повноцінний Electron/GUI автоматично не запускався; GUI-приймання залишається користувачеві.

На етапі 1.4 успішно виконано `pnpm typecheck`, `pnpm build` та `git diff --check`. Цільово звірено конфігурації, шляхи Main/preload/renderer, імпорти CSS/герба, незалежність профілів, залежності та склад відстежуваних файлів. Серверного runtime, удаваних кадрових операцій, секретів чи персональних кадрових записів не виявлено. `reference/` виключено через кореневий `.gitignore`. Перевірка не є повним аудитом безпеки.

На етапі 1.3 візуально підтверджено герб у built-Electron через `file://` і після перезапуску; перевірено перехід до працівників, Tab/Enter до відпусток, видимий фокус і повернення через breadcrumbs. На етапі 1.4 GUI повторно не перевірявся. Повний перелік нижче залишається відкритим для остаточного приймання.

Якщо у блоці установи видно старий UsersRound, спочатку перевірте, чи не залишився старий dev-сеанс/екземпляр. На 1.3 актуальні PNG, імпорт, `file://`-URL та CSP були коректні; CSS-виправлення не знадобилося. Закрийте відповідне вікно, зупиніть dev Ctrl+C у його терміналі, виконайте `pnpm build`, потім `pnpm start:built`. Остання команда не перебудовує `dist`, а single-instance може сфокусувати старе вікно.

## Відкрите ручне приймання Windows

Не вважайте наведені пункти виконаними лише через їх наявність у документі. Для кожного зафіксуйте результат, Windows, масштаб і розмір вікна під час приймання.

- [ ] `pnpm dev`: запуск, українські тексти, HMR; закриття Electron і завершення dev-сеансу, повторний запуск.
- [ ] Built після `pnpm build`: запуск, закриття та повторний запуск; другий запуск того самого режиму фокусує одне вікно.
- [ ] Усі сім розділів: назва, активний пункт, breadcrumbs, повернення на головну; налаштування внизу sidebar.
- [ ] На головній герб без обрізання/спотворення, назва громади, окремий бренд HromadaHR; немає KPI та удаваних операцій.
- [ ] Tab/Shift+Tab, Enter/Space, skip-link і видимий фокус; підказки піктограм у компактному sidebar.
- [ ] Вузьке й низьке вікно: адаптація головного блоку, доступність sidebar та налаштувань, перенесення українських назв.
- [ ] Windows 100%, 125%, 150%, 200%: читабельність і відсутність горизонтального переповнення в кожному режимі.
- [ ] Зупинений Vite та вимкнений інтернет: `pnpm start:built` відкриває актуальний інтерфейс і герб без помилок.
- [ ] Dev/built використовують різні `%APPDATA%`-профілі й можуть працювати паралельно без впливу на HromadaAID.
- [ ] 2.1: після нового запуску dev і built у «Налаштуваннях» показано `HromadaHR · Версія 0.1.0`; сім розділів і попереднє оформлення збережено.
- [ ] 2.1: у DevTools Electron `Object.keys(window.hromadaHR)` містить лише `system`, а `Object.keys(window.hromadaHR.system)` — лише `getInfo`; виклик `await window.hromadaHR.system.getInfo()` повертає `ok: true` та тільки name/version/mode (відповідний dev/built).
- [ ] 2.1: відкритий напряму Vite у звичайному браузері показує в налаштуваннях «Версія застосунку недоступна» без падіння інтерфейсу.
