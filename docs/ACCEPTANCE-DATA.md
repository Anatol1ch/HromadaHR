# Синтетичні дані Windows-приймання

Пакет 8.1; функціональний baseline `ea47b13f4a4b08665279307bc9f66db63703648a`, HromadaHR 0.1.0 / SQLite v21. Вводити вручну тільки в ізольованому Windows-профілі за [протоколом](ACCEPTANCE-WINDOWS.md). Це вигадані особи й підтверджені тестові числа, а не визначення законних прав реальних працівників. Жодних РНОКПП, паспортів, банківських реквізитів або production-копій.

## Порядок і дата

1. Записати в протокол локальну календарну дату **D** на тестовому ПК. Main обчислює прогнози на сьогодні; UI не має довільного as-of перемикача. Не змінювати системний час основного ПК. Якщо тест повторюється іншого дня, звірити D, знову явно встановити опорну дату D або використовувати новий ізольований профіль.
2. У Довідниках створити підрозділи «ТЕСТ — Адміністрація» / «ТЕСТ — Служба забезпечення», посади «ТЕСТ — Спеціаліст» / «ТЕСТ — Фахівець забезпечення». Порядок можна міняти в B-сценаріях.
3. Внести сім працівників нижче. Усі по батькові — «Тестович» або «Тестівна» як зазначено, усі примітки починати «СИНТЕТИЧНИЙ ТЕСТ». Не використовувати справжні посади для правового висновку.
4. Внести показники, потім права/періоди. Зафіксувати копію **S0** після підготовки працівників, до витрат днів; **S1** — після документів/серій/зв’язку. Це позначення копій у протоколі, не перейменування службових backup-файлів.
5. Модифікаційні сценарії виконувати по порядку. Перед повтором D/E відновити погоджену синтетичну S0/S1 через штатний restore або почати з нового тестового Windows-профілю. Не видаляти каталог БД скриптом.

Всі 30/5/12/18/3/2/0 — довільно підтверджені тестові залишки, не юридичні нормативи. Нові періоди/підтверджені права додавати лише явними діями відповідного сценарію. Якщо UI не пропонує точної історичної строки, зафіксувати умови й BLOCKED; не обходити валідацію прямим SQL. Новий поточний період не змішувати з initial_balance. Перенесення залишку перевіряється його доступністю з історичного періоду, а не автоматичним дублюванням днів у новому році.

Після кейсу повернути S0, щоб E02 знову слугував профілем неповних даних. Еталон: tests/service-calculations.test.mjs, baseline identity/zero/opt-out.

## Контрольні надання й документи

- **L01, E05, щорічна:** 05.04.2027–20.04.2027, 16 к. дн., номер `001-т`, дата розпорядження 12.11.2026. Явно застосувати FIFO: 5 днів із 2024 + 11 із 2025. Доступно після цього 0/1/18. Перед окремим ручним розподілом відновити S0: 10 із 2025 + 6 із 2026 → використано 0/10/6, доступно 5/2/12. Скасування повертає використання, запис залишається в історії. Джерело: tests/leave-registration.test.mjs, тест FIFO/manual allocation.
- **L02, E06, нестача:** спробувати 05.04.2027–08.04.2027 (4 дні) проти залишку 2; без нового підтвердження днів операція не завершується. Чинним BalanceEditor явно змінити підтверджені дні initial_balance за 2024 рік із 2 на 4 (синтетичне коригування), повернутися до тієї самої чернетки й зареєструвати 4: використано 4, доступно 0. Записати коригування до остаточного save; перед повтором повернути S0.
- **L03, E01, межа років:** 31.12.2027–02.01.2028 = 3 к. дн.; **L04:** 28.02.2028–01.03.2028 = 3 к. дн. Ці значення перевіряють календарний підрахунок (tests/leave-registration.test.mjs), не право на конкретну тривалість. Після проби скасувати або відновити S0 перед наступним контрольним списанням.
- **L05:** початок 31.12.2026, кінець 02.01.2027 — відхилення нової реєстрації через чинну межу 01.01.2027; не реєструвати перехідну відпустку прихованим способом, для попередніх даних діє historical balance модель.
- **L06, E07:** по одному дню навчальної/УБД/чорнобильської в різні дати січня 2027, лише після явного тестового підтвердження відповідного права; річні лічильники збільшуються на фактично внесені дні. Обмеження 14/16, де застосовні, звіряти як реалізовані model limits shared/leave.ts + tests/special-leaves.test.mjs, а не визначення правової належності вигаданої особи.

Серії створюються вручну лише в тестовому довіднику: **TEST-A / «ТЕСТ — Серія»**, **TEST-B / «ТЕСТ — Серія»**, обидві head_order, pattern `{N}-т`, minDigits=3, startAt=1; **TEST-Y / «ТЕСТ — Річна»**, head_order, `{N}/{YYYY}`, minDigits=1, startAt=1. Це не seed і не номенклатура громади.

На чистих TEST-A/TEST-B перші автоматичні документи за 12.11.2026 мають номер `001-т` незалежно. Для зв’язку з L01 вибрати конкретний документ TEST-A, одного E05 і ту саму дату. L01 не може одночасно отримати TEST-B. TEST-Y: перші документи за 31.12.2026 і 01.01.2027 отримують `1/2026` та `1/2027`. Ручне зайняття `015-т` у TEST-A/2026 робить позицію 15 зайнятою і для `15-т`, наступний auto — `016-т`. Після delete/перенумерування позиції не звільняються. Джерело: tests/document-numbering.test.mjs та shared/document-numbering.ts. Слідкувати за порядком: до тесту позиції 15 не створювати номери понад 15.

Документ без серії: номер `ТЕСТ-ВІЛЬНИЙ-01`, без працівника, title «СИНТЕТИЧНИЙ ТЕСТ — загальний документ». Other/customKind: «ТЕСТ — довідка», номер `ТЕСТ-ІНШИЙ-01`. Для видалення працівника створити окрему тимчасову вигадану особу «Тимчасовенко Видалюваний Тестович» без показників і документів; сім основних профілів не видаляти до завершення пакетів.
