# Специфікація для погодження · 4.8.1

**Працівник → вид → поточна ситуація → дія.** Верхній контекст спільний для трьох вкладок. Вид подієвої відпустки веде до журналу, а вкладка залишків працює з трьома періодними видами. Під час повернення з прав і журналу зберігається останній періодний вид працівника. Якщо його ще не вибирали, відкривається щорічна основна відпустка. Журнал і права зберігають доступ до всіх шести фактичних видів. Виробничий загальний журнал і його фільтри залишаються доступними.

## Представлення станів

| Вісь | Стан | Що показати |
| --- | --- | --- |
| Поточне право | Підтверджено / не перевірено / немає | Самостійний статус і контекстна дія перевірки. Невідомий статус не означає відмову. |
| Періодні дні | Немає / 0 / позитивні / частково внесені | Порожній рядок без підстави для списання. Нуль підтверджений явно. Підсумок часткового обліку охоплює внесені періоди. Пропозиція наступного періоду підписана окремо. |
| Історія | Є дні або записи за відсутнього права | Показати фактичні дані. Для нового підтвердження застосувати чинне правило перевірки права. |
| Подієві види | Рік початку та реєстрації | У журналі показати дні активних надань та окремо скасовані записи. Для навчальної універсального ліміту немає. Для спеціальних видів показувати чинне облікове обмеження, без висновку про персональну законність надання. |

## Переходи

1. **Право.** За контекстною дією відкрити права того самого працівника й виду. Зміна права зберігається явно. Дні та записи від цього не змінюються.
2. **Дні.** Історичний запис і підтвердження нового періоду залишаються розрізненими. Для дітей рік дає межі 01.01–31.12. Для стажу дата визначена кадровиком. Її збереження оновлює пропозиції, а підтвердження днів залишається наступною окремою дією. Після збереження дати її зміна не відмотується скасуванням редактора днів. Якщо редагування днів уже розпочалося, спершу зберегти або відкинути ці зміни. Збережені періоди не перебудовуються.
3. **Реєстрація.** Відкрити за вибраним контекстом. У формі з загального журналу зберегти доступ до явного вибору працівника й виду. Відсутні дні показують дію «Внести дні й повернутися». Після її натискання чернетка містить ідентичність працівника й виду, дати та сирі рядки введення, тривалість, підставу, реквізити, пояснення, розподіл, а для редагування також ID і ревізію. Чернетка живе в пам’яті вкладки до явного завершення або закриття. Перезапуск застосунку її не відновлює.
4. **Повернення.** Успішне внесення днів повертає до тих самих полів та перечитує доступність. Значення розподілу зберігаються за ID, непридатні значення не списуються і підсвічуються для виправлення. Нові рядки починаються з нуля. FIFO застосовується лише явно, заміна введених значень вимагає підтвердження. Відмова від змін днів повертає ту саму чернетку. Повторне відкриття редактора днів не створює відпустки.
5. **Завершення.** Підтвердження відпустки окреме від підтвердження днів. Успіх веде до журналу з тим самим працівником, видом і роком початку. Скасування зберігає причину та історію.

## Відмови й захист

- Помилка читання прав або доступності – показати помилку та повтор. Не підміняти статусом «немає права» чи нулем.
- Помилка запису днів – лишити редактор і чернетку реєстрації. Після повернення перечитувати Main; він є джерелом доступності.
- Некоректні дати, перетин, недостатні дні чи відсутня підстава – пояснити конкретну дію поруч із відповідним полем або розподілом. Діє обліковий початок 01.01.2027.
- Застаріла ревізія – залишити чернетку для порівняння, вимагати відкриття актуального запису. Невизначений результат – перевірити фактичний запис до повторного запису. Той самий запит реєстрації повторити з тим самим request ID; для зміненого набору даних потрібен новий ID. Атомарність і захист від подвійного списання залишаються в Main.
- Під час операції блокувати повторний запуск і зміну контексту. Закриття незбереженої форми потребує підтвердження. Виробничий діалог має використовувати чинні Modal, ConfirmDialog, DateField і focus guard. Демо використовує нативний dialog і confirm.

## Окреме погодження

1. Погодити контекстний журнал за працівником і видом та повернення з редактора днів. Визначити місце тимчасової чернетки у виробничому Renderer і поведінку при переході з модуля.
2. Погодити дві явні операції для стажу. Спільний атомарний запис дати й днів виходить за межі цієї пропозиції.
3. Погодити, як показувати конфлікт чернетки з новою ревізією та чи потрібне окреме порівняння. Демонстрація не моделює збої процесу Main, паралельне редагування чи відновлення після перезапуску.
4. Будь-які зміни правил набуття права, лімітів, допустимості списання або життєвого циклу запису потребують окремого рішення. У цьому прототипі вони залишаються чинними.
