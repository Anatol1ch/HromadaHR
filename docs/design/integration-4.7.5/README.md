# 4.7.5 · Розподіл відпусток та UI-корекції

Перевірено виробничу збірку у справжньому Electron з ізольованим профілем і синтетичними записами SQLite.

- Панель розподілу – [широка](acceptance-allocation-wide.png), [вузька](acceptance-allocation-narrow.png), [вузька при 200%](acceptance-allocation-narrow-200.png).
- Список років – [відкриття вниз](acceptance-year-wide.png), [відкриття догори при 200%](acceptance-year-200.png).
- Пошук працівника – [100%](acceptance-search-wide.png), [200%](acceptance-search-200.png).

Підтверджений період починався після завершення відпустки. У GUI вручну збережено розподіл 2 + 4 дні, відкрито його для редагування та скасовано запис. IPC підтвердив розподіл і відсутність хибного allocationWarning. Автоматичні тести перевірили відхилення невідомого ID і перевищення залишку, консервативний FIFO, повернення днів та читання старого запису після відновлення.

У базовій збірці відтворено окремий 2-px контур усередині SearchField. У новій збірці фокус позначає обгортка, а довгі ПІБ і підрозділи переносяться. Геометрію панелі, пошуку й списку років перевірено при 100%, 150% і 200% масштабу Electron на широких і вузьких конфігураціях. Відкритий список з роками 2027–2042 перепозиціонувався при зміні розміру й масштабу. Він залишався в межах viewport та прокручувався всередині.

Пройшли `pnpm typecheck`, `pnpm build`, `git diff --check`, 33 цільові тести та фінальний `pnpm test` із 171 тестом і Electron storage smoke. Системний DPI Windows, миша та повний обхід клавіатурою на робочому дисплеї залишаються для ручного приймання.
