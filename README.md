# HromadaHR

Незалежний локальний настільний застосунок для кадрового обліку в органах місцевого самоврядування України. Реалізовано технічну основу (1.1) та інтерфейсну оболонку в стилі сімейства Hromada (1.2).

Стек: Electron 44.7.1, React 19.2.9, TypeScript 5.9.3, Vite 8.3.4, @vitejs/plugin-react 6.1.2. Ідентичність: `hromada-hr`, HromadaHR 0.1.0, `local.hromadahr`.

## Вимоги та запуск

Windows 10/11, Node.js 24.22.1, pnpm 11.25.0. Інтернет потрібен для першого встановлення залежностей і завантаження Electron; зібраний застосунок працює локально без інтернету.

```powershell
pnpm install --frozen-lockfile
pnpm typecheck
pnpm dev
```

Dev запускає Vite на `http://127.0.0.1:5176` і Electron. Закриття Electron або Ctrl+C завершує dev-сеанс. Зміни React застосовуються через HMR; після змін Main/preload перезапустіть `pnpm dev`. Зайнятий порт призводить до помилки, сторонні процеси не завершуються.

```powershell
pnpm build
pnpm start:built
```

`build` перевіряє типи й створює `dist/index.html`, ресурси renderer, `dist-electron/main.js` та `dist-electron/preload.cjs`. `start:built` відкриває ці локальні файли без Vite й не виконує збірку. Це запуск через встановлену dev-залежність Electron, а не інсталятор.

Профілі: `%APPDATA%\HromadaHR-dev` для `pnpm dev`, `%APPDATA%\HromadaHR` для built/майбутнього production. Профіль обирається перед single-instance lock; повторний запуск того самого режиму фокусує наявне вікно.

`postinstall` викликає штатну команду `install-electron`, щоб бінарний Electron було завантажено під час встановлення залежностей, до офлайн-запуску. `pnpm-workspace.yaml` містить лише дозвіл build-скриптів Electron для pnpm 11; серверного або багатопакетного workspace немає.

## Межі етапу

Навігація між «Головна», «Огляд», «Працівники», «Відпустки», «Стаж і ранги», «Документи» та «Налаштування» працює через локальний React state; вибір розділу не зберігається між запусками. Крім початкового екрана, розділи показують стан «Функціональність ще не реалізована», а не порожній реєстр.

Немає SQLite, IPC-операцій, авторизації, кадрової логіки, сервера, оновлень, пакування чи інсталятора. Preload не відкриває жодних API. У production CSP забороняє мережеві з'єднання renderer; dev дозволяє локальний HMR.

Технічні орієнтири цільово переглянуто в [HromadaAID на зафіксованому коміті](https://github.com/Anatol1ch/HromadaAID/tree/16582ce252086bb39d2276ac3c1de90e4895f21f); залежності та історія проєктів незалежні.

## Стилі та компоненти оболонки

Джерело візуальних правил — `src/styles.css` і компонування `src/App.tsx` HromadaAID на тому самому коміті. Перенесено лише потрібні правила, без стилів реєстрів допомог, форм і звітів:

- `src/styles/tokens.css` — палітра, відступи, радіуси, геометрія контролів і кольори повідомлень.
- `src/styles/base.css` — Segoe UI, базові правила, keyboard focus, skip-link і reduced motion.
- `src/styles/components.css` — основна кнопка, `Alert` та `DataState`.
- `src/styles/shell.css` — sidebar, бренд, breadcrumbs, topbar, контент, головний екран і адаптивні правила.

`Alert` перенесено зі збереженням ролей, дій і закриття. `DataState` зберігає loading/empty/search та отримав окремий `planned` для нереалізованих можливостей. Оболонку адаптовано до HromadaHR без авторизації та серверного стану. Єдина додана залежність — `lucide-react` 0.577.0; `UsersRound` залишається основним знаком бренду HromadaHR.

Збережено геометрію Hromada: sidebar 258 px (244 px до 1280 px, панель піктограм 68 px до 1100 px), topbar 68 px, контент до 1500 px, стандартну кнопку 44 px, вихідні hover/focus/active-стани та адаптацію відступів. Для довгих назв навігація допускає перенесення, висота пункту щонайменше 49 px. Окремої мобільної версії немає.

У завданні 1.2.1 запроваджено власну палітру: `--accent: #6F5AA5`, `--accent-strong: #594681`, `--accent-soft: #EFEAF7`, фон `#F7F6FA`, межі `#E4DFEC`, текст `#252738`, допоміжний текст `#687084`, картки `#FFFFFF`. Семантичні кольори успіху, помилки та попередження збережено незалежно від акценту. Шрифти, відступи та структура оболонки не змінені.

Розрахований контраст: білий текст кнопки 5,70:1 (hover 8,02:1), основний текст на фоні 13,69:1, допоміжний текст на білому 4,95:1 і на фоні 4,60:1, темний акцент на світлому 6,79:1. На бузковій поверхні використано темний акцент, оскільки допоміжний `#687084` дає лише 4,19:1. Фокус має контраст щонайменше 4,83:1 на використаних поверхнях.

На головній показано герб Вишнівської селищної територіальної громади з `assets/community-coat.png` з пропорційним вписуванням (`object-fit: contain`). Це побайтова копія наданого локального `reference/ГЕРБ.png`, який залишається незмінним; застосунок не залежить від каталогу `reference`. Герб є окремим знаком установи й не замінює брендинг HromadaHR. Механізму вибору гербів немає.

## Ручна перевірка Windows

1. Запустіть `pnpm dev`: перевірте українські тексти, заголовок HromadaHR і HMR після зміни renderer.
2. Закрийте вікно; переконайтеся, що dev-сеанс завершився, і повторіть запуск.
3. Виконайте `pnpm build`, закрийте Vite та вимкніть інтернет. Запустіть `pnpm start:built`: перевірте ті самі тексти й відсутність помилок завантаження.
4. Повторіть `pnpm start:built` з іншого термінала: має фокусуватися одне вікно. Закрийте його та перевірте новий запуск.
5. Перевірте окремі каталоги профілів HromadaHR-dev і HromadaHR, а також можливість одночасного запуску двох режимів.
6. Перейдіть усіма сімома пунктами навігації, кнопкою «Перейти до огляду» та крихтою «Робочий простір»; перевірте активний пункт, назву й інформаційний стан. «Налаштування» мають залишатися внизу sidebar.
7. Перевірте Tab/Shift+Tab, Enter/Space, видимий focus і посилання «Перейти до вмісту». У компактному sidebar назви доступні через підказки та accessibility labels.
8. Перевірте Windows scale 100/125/150/200%, вузьке й низьке вікно: панель піктограм, перенесення українських назв, читабельність і контраст, відсутність горизонтального переповнення та доступність налаштувань через прокручування sidebar.

Повноцінні сторінки розділів визначатиме окреме завдання 1.3; завершення документації — 1.4.
