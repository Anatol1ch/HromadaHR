# HromadaHR

Незалежний локальний застосунок кадрового обліку для органів місцевого самоврядування України, Windows 10/11, орієнтовно до 30 працівників. Версія **0.1.0**. Етап 03 інтегровано в main. Етап 3.5 спрощує кадровий реєстр перед обліком відпусток.

Стек: Electron 44.7.1, React 19.2.9, TypeScript 5.9.3, Vite 8.3.4, better-sqlite3 13.0.3 та Zod. Один автономний застосунок без окремого сервера, HTTP API, авторизації, паролів, ролей або шифрування SQLite/копій.

## Що реалізовано

- SQLite у Main із WAL, зовнішніми ключами та міграціями 1–5. Картка зберігає ПІБ, необов’язкову дату народження, тип працівника, окрему дату прийняття, актуальну посаду й підрозділ.
- Реєстр із двома групами працівників, пошуком, фільтрами та незалежним сортуванням. Модальні створення, перегляд, редагування і підтверджене видалення працюють через дев’ять кадрових IPC-операцій.
- Компоненти, клавіатурна взаємодія, календарі та сповіщення адаптовані з HromadaAID; власна стримана сиренево-фіолетова палітра HR. Користувацькі дати — ДД.ММ.РРРР, час — ДД.ММ.РРРР ГГ:ХХ; внутрішні дати — ISO.
- Стартова заставка щонайменше 3,5 секунди від монтування App; очікування фактичної готовності SQLite, негайний RecoveryScreen при помилці. Звичайне максимізоване вікно, власний бренд та герб громади.
- Одна логічна резервна копія: один перевірений SQLite-знімок, незалежно опублікований у двох обов'язкових місцях. SHA-256 пов'язує нові дублікати; часткові помилки показуються явно, автоматичний повтор насамперед доповнює той самий образ. Зберігаються 14 автоматичних копій на місце; ручні не ротуються.
- Каталог реальних копій, окремий обмежений діагностичний журнал, відновлення конкретного знімка або вибраного файла. Захищена підготовка, одноразовий token, обов'язкове системне підтвердження, захисна копія та recovery journal/rollback; пошкоджену БД не підміняють порожньою.
- Налаштування, «Про програму», підтримка та дозволені зовнішні контакти. Ctrl +/−/0 і NumPad змінюють реальний масштаб Electron та зберігають його між перезапусками; видимого zoom-selector немає.

Основні GUI-сценарії перевіряв користувач. Повне формальне приймання всіх сценаріїв, зокрема аварійного відновлення, **не підтверджено**. Завершення реалізації не означає підтвердження готовності до експлуатації з реальними кадровими даними.

Міграція v5 разово очищує погоджені тестові кадрові записи після захисної копії та зберігає довідники. Відновлення v4 або старішої копії теж запускає міграцію v5. Для повернення актуальних працівників потрібна копія v5.

## Ще не реалізовано

Наступний напрям — **етап 04: облік відпусток**, за окремим завданням. Контроль чинних надбавок, рангів і додаткової відпустки за вислугу, документообіг, автоматичні оновлення, пакування/інсталятор та релізний pipeline не реалізовані. Розділи й вкладки майбутніх модулів — явні заглушки без фіктивних даних. Авторизація, ролі та шифрування остаточно виключені, а не відкладені.

## Підготовка середовища та dev

Встановіть Node.js 24.22.1 і pnpm 11.25.0. Перше встановлення залежностей і бінарного Electron потребує інтернету. У корені репозиторію виконайте:

```powershell
pnpm install --frozen-lockfile
pnpm typecheck
pnpm dev
```

Dev використовує `http://127.0.0.1:5176/`. Після змін Main/preload перезапустіть dev; React підтримує HMR. Закриття Electron або Ctrl+C завершує dev-сеанс.

## Production-збірка та локальний запуск

```powershell
pnpm build
pnpm start:built
```

Built завантажує локальні ресурси без Vite та інтернету через встановлений Electron. `start:built` не перебудовує `dist` і не створює інсталятор. Якщо видно старий екран, закрийте попередній екземпляр, зупиніть старий dev-сеанс і повторіть обидві команди.
