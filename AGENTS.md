# Правила роботи з HromadaHR

- Перед роботою прочитайте `docs/HANDOFF.md`; далі цільово перегляньте потрібні частини `docs/ARCHITECTURE.md` і `docs/DECISIONS.md`. Розрізняйте фактичну реалізацію та погоджені майбутні рішення.
- Працюйте лише в цільовому репозиторії `Anatol1ch/HromadaHR`. HromadaAID — лише джерело для читання; не змінюйте його та не приєднуйте історію чи кодову базу через fork, submodule або subtree.
- Перед змінами перевіряйте гілку, HEAD і Git-стан. Обов'язково зберігайте сторонні зміни; не скидайте й не перезаписуйте їх.
- Робіть мінімальні цільові зміни. Фактичний код і результати перевірок мають пріоритет над документацією; уточнюйте застарілу документацію.
- Не проводьте повний аудит репозиторію без конкретної потреби або окремого завдання. Перевіряйте файли й сценарії, яких стосується зміна.
- Не додавайте необґрунтованих абстракцій, залежностей або майбутньої предметної логіки. Застосунок локальний, без окремого сервера та HTTP API.
- Зберігайте `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true` і стандартну web security. Забороняйте сторонні вікна й неконтрольовану навігацію.
- Renderer не має прямого доступу до Node.js, Electron чи файлової системи. Майбутні IPC-операції — лише явно визначені типізовані методи через preload/contextBridge, з перевіркою аргументів і відправника в Main.
- Зберігайте незалежні профілі HromadaHR і HromadaHR-dev. Не змінюйте встановлений HromadaAID чи його налаштування.
- Обирайте автоматичні перевірки за ризиком: TypeScript, build, шляхи ресурсів, модель безпеки, `git diff --check`; для суттєвої логіки додавайте змістовні тести. Не створюйте GUI snapshot-тести для порожнього інтерфейсу.
- Не створюйте інсталятори, пакування, релізи або публікації без окремої вказівки.
- Використовуйте pnpm. Після зміни залежностей оновлюйте lockfile. Не переходьте до наступних етапів без завдання.
- Не реалізовуйте майбутні функції лише тому, що вони записані в DECISIONS. SQLite, авторизація, кадрові модулі, резервування та оновлення потребують окремих завдань і погодження невизначених деталей.
- `reference/` — виключно локальні матеріали: не видаляйте, не змінюйте й не додавайте їх до Git. Ресурс застосунку — `assets/community-coat.png`.
- Не додавайте до Git залежності, результати збірки, Electron-профілі, логи, секрети чи персональні кадрові дані. Зазначайте фактичний обсяг GUI-перевірок, не позначайте ручні сценарії виконаними без перевірки.
